# Regex em JS (Equipe 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar as 6 etapas do laboratório de regex em JavaScript (pasta `equipe_02_javascript/`) e um site de apresentação em Docker com slides, demos ao vivo, Regex Invaders e Regex Arena.

**Architecture:** Monorepo pnpm. `equipe_02_javascript` é um pacote JS puro sem dependências (`@regex-js/etapas`) consumido por `apps/web` (Vite+React+TS) e `apps/server` (Fastify+WebSocket, TS via type stripping do Node 24). Uma imagem Docker serve tudo na porta 3000.

**Tech Stack:** Node 24, pnpm 9, node:test, Vite 6, React 18, react-router-dom 6, qrcode, Fastify 5, @fastify/static, @fastify/websocket, pptxgenjs, Chrome headless (PDF).

**Spec:** `docs/superpowers/specs/2026-11-09-regex-js-design.md`

## Global Constraints

- Código de entrega: ESM, zero dependências, só `RegExp` nativa e módulos `node:`; roda com Node ≥ 20.
- Validação de campo sempre ancorada `^…$`; classes ASCII explícitas (`[0-9]`, `[A-Za-z0-9_]`), nunca `\d`/`\w` nos padrões das etapas.
- Regex das etapas declaradas como literais no topo do módulo e exportadas (o site as exibe).
- Textos de interface, comentários e documentação em português do Brasil.
- URL pública padrão: `https://regex-js.tccodes.com.br` (`VITE_PUBLIC_URL`).
- Arena: padrão ≤ 100 caracteres, flags só `i`/`u`, timeout de avaliação 200 ms, 1 envio/s por jogador, apelido ≤ 16 caracteres.
- Pontuação Arena: `500 + round(500 × restanteMs/duracaoMs) + max(0, 300 − 10 × padrao.length)`.
- Servidor TS usa apenas sintaxe apagável (sem enum, namespace, parameter properties); imports com extensão `.ts`.

## Review Focus

1. Regex com `/g` reutilizada em `test()` mantém `lastIndex` e alterna true/false → funções públicas nunca reutilizam regex global com `test` (teste em Task 1).
2. Entrada vazia (λ) em todo validador → retorna inválido sem lançar (testes em Tasks 1, 2, 3, 6).
3. Arquivo de log com CRLF (Windows) e linha final vazia → linhas em branco ignoradas, `\r` removido, contagens iguais (teste em Task 5).
4. Regex catastrófica `(a+)+$` enviada na Arena → resposta "tempo excedido" e servidor segue respondendo (teste em Task 8).
5. Regex sintaticamente inválida digitada no playground/jogos → mensagem de erro, sem quebrar a página (verificação manual em Tasks 10, 12, 13; teste do avaliador em Task 8).
